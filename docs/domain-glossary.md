# Domain Glossary — German Vehicle Registration (ZulexGO)

- **Außerbetriebsetzung (de-registration)** — Officially taking a vehicle out of operation. Vehicle tax and insurance stop automatically via KBA notification. The MVP service.
- **KBA (Kraftfahrt-Bundesamt)** — Federal Motor Transport Authority. Central registry; processes online applications, issues final decision.
- **Zulassungsbehörde / Zulassungsstelle (registration authority)** — Local district authority responsible for the vehicle; applications route to it. Its **i-Kfz status** (`online` / `unavailable` / `offline`) determines automatic vs. manual processing.
- **i-Kfz (internetbasierte Fahrzeugzulassung)** — German legal framework for online vehicle registration. Security codes replace in-person identification.
- **Zulassungsbescheinigung Teil I (registration certificate part 1)** — Vehicle document kept in the car ("Fahrzeugschein"). Concealed **7-character security code**, scratched free to de-register; scratching voids the document.
- **Zulassungsbescheinigung Teil II (Fahrzeugbrief)** — Ownership document. Not needed for de-registration; a Neuzulassung needs its number (1–20 characters in the Zulex API) and its security code.
- **Teil II security code** — Concealed code on a Teil II issued for online registration; with the Teil II number it proves possession of the document. The API asks for at least one character and says no more about its format (launch plan Q56). Treated as a secret, like the codes above.
- **Kennzeichen (licence plate)** — District prefix (1–3 letters, may contain Ä/Ö/Ü) + 1–2 letters + 1–4 digits. Cars have two plates; motorcycles and trailers one.
- **Plakette / Siegel (plate seal)** — Official sticker on each plate hiding a **3-character security code**; scratching invalidates the plate. Rear code always required, front code only for two-plate vehicles.
- **Sicherheitscode (security code)** — The scratch-off codes above. Legal proof of possession authorizing online de-registration — treat as secrets.
- **VIN / FIN (Fahrzeug-Identifizierungsnummer)** — Vehicle identification number, up to 17 characters, printed in Teil I.
- **eVB-Nummer (elektronische Versicherungsbestätigung)** — The insurer's electronic confirmation that the vehicle is insured, which a registration needs. Seven characters, letters and digits except I and O (the Zulex API's pattern, which is not anchored; ours is). Treated as a secret.
- **Halter (keeper)** — The person the vehicle is registered to, and who answers for its use. The Zulex API calls them `owner`, and so does the code (`Owner`, `ownerInfo`).
- **Antrag (application)** — One submission to the authority. Identified by our order reference `ZG-XXXXXX` (`ApplicationReference`); the Zulex API gives it its own `applicationId`, stored as `zulexApplicationId`.
- **Bescheid (notice)** — Formal decision document from the registration authority (confirmation or rejection).
- **Abmeldebescheinigung (deregistration confirmation)** — Official PDF proving de-registration (`DEREGISTRATION_CONFIRMATION` document). Customer's end deliverable.
- **Temporary registration certificate** — A document the Zulex API lists for a registration (`TEMPORARY_REGISTRATION_CERTIFICATE`), beside the registration confirmation (`REGISTRATION_CONFIRMATION`). What it allows the customer until the permanent documents arrive: open (launch plan Q55).
- **Gebühr (fee)** — Statutory authority fee, returned as a `FEE` document; shown inside the customer's total price.
- **Kennzeichenreservierung (plate reservation)** — Reserving the plate combination for later reuse. Removed from MVP scope.
- **Saison- / E- / H-Kennzeichen** — Seasonal, electric, historic plate variants. Not representable in the de-registration request — open API question.
- **Wunschkennzeichen (wish plate)** — A plate combination the customer picked and reserved beforehand on the authority's own portal. The Zulex API takes it only with the PIN (3–8 characters) from that reservation, and has no reservation endpoint of its own.
- **Zusatzleistungen (add-ons)** — Standard or carbon plates, fine-dust sticker (Feinstaubplakette), shipping (with plates only), and the THG-Quote for electric vehicles (a greenhouse-gas quota the owner may sell; free for the customer). Priced in `src/core/domain/payment/pricing.ts`. Plates and sticker are ordered and charged only after the KBA has completed the service, never if it rejects it. Not sold yet (launch plan Q41, Q42).
- **Neuzulassung (registration)** — Registering a vehicle that has had no plates before. The Zulex API files it at `POST /registration-applications`, and the authority is found by the keeper's postcode (`GET /registration-authorities?postcode=`), not by a plate prefix. Priced in `SERVICE_PRICES.newRegistration`; the code calls it `newRegistration`, never just "registration", which means filing with the KBA.
- **Wiederzulassung (reactivation)** — Re-registering a de-registered vehicle. Future service, natural follow-up to de-registration.
- **Pre-authorization (Vorautorisierung)** — Stripe payment hold (manual capture): funds reserved at checkout, captured later. Cards only; SEPA Direct Debit can't be held, captured at checkout. Card hold lasts 7 days (Visa, Mastercard), then Stripe releases it. When a hold is captured: open (launch plan Q7).
- **Verimi** — Identity-verification provider, added later. Customer gets Verimi link by email, verifies with selfie + ID-card scan (~90 s); status 2 → 3, before KBA submission. Who integrates it, and whether de-registration needs it: open (launch plan Q1–Q4).
- **Status 2 / 3** — Between payment (1) and filing at the KBA (4): waiting for the customer's identity verification (`awaiting_identity_verification`), then the identity confirmed (`identity_verified`). Only a service that verifies the customer's identity passes through them (`requiresIdentityVerification`); the others go from 1 to 4.
- **Kfz-Steuer-Lastschriftmandat (vehicle-tax direct-debit mandate)** — Vehicle tax is collected by SEPA direct debit from the keeper's account, so a Neuzulassung carries the account (IBAN, BIC, bank name, country: `sepaInfo` in the Zulex API, which marks it optional). Treated as a secret.
- **Bearbeitungsgebühr (processing fee)** — 19.99 €, fixed regardless of service type; covers Zulex API fee and administration; it is part of the service price, not added to it. Retained when customer cancels after correctable failure (5b) or application can't be corrected (5c); rest refunded. Must be shown before payment.
- **Status 5a / 5b / 5c** — The three outcomes: completed; failed, correction possible (customer corrects or cancels); failed, correction not possible (new application, refund minus 19.99 €).
- **Stornierung (cancellation)** — Customer's option at 5b to stop instead of correcting. 19.99 € retained, rest refunded; later resubmission is a new order at full price.
- **SEPA-Lastschrift (SEPA Direct Debit)** — Bank-account payment in the Payment Element. Captured at checkout, settles over several business days; customer can dispute with their bank for up to 13 months.
- **Status link** — Unguessable URL giving account-free access to the personal status dashboard; sole access credential, delivered by email. Reusable until a new token replaces it; it does not expire.
- **Widerrufsrecht (right of withdrawal)** — 14-day consumer cancellation right; shown with T&Cs before payment. How it interacts with the 19.99 € processing fee, and whether an immediate-performance waiver is still needed: open (launch plan Q13).
