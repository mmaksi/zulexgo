**Why:** Neuzulassung orders wait for the customer's identity verification after payment and before filing, so the status machine gains two statuses (`awaiting_identity_verification`, `identity_verified`) and the database must store them.
**Breaks without it:** the first order to reach either status is refused by the `application_status` check, so a Neuzulassung order could not be saved after payment; de-registration is unaffected, since it never enters them.
**Live table:** safe; the check is replaced inside one transaction with a longer list, so every stored row still passes and no row is rewritten. `down.sql` fails while any order, or any `status_history` row of an order that has since moved on (it uses the same domain), holds one of the two new statuses, which is the right answer: that history must not be silently lost.
