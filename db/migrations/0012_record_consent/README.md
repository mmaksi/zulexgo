**Why:** the customer ticks the AGB with the withdrawal notice, the early-start waiver and, for a Neuzulassung, a power of attorney before paying, and an order has to be able to prove it (launch plan D9, Q13, Q46). `agb_version` and `consent_at` have existed since 0001 and nothing wrote them; checkout now does, and refuses to make an order without them. The power of attorney has its own text, hence its own version column.
**Breaks without it:** the adapter writes `power_of_attorney_version`, so every insert and update fails; and nothing stops a half-recorded consent (a version without a time) from being stored.
**Live table:** safe. It adds a nullable column and a check that every existing row satisfies, since none has a consent (the columns were never written). Orders made before this migration keep no consent, which the domain allows (`Application.consent` is optional) for exactly those rows, dev's and staging's seeded orders included. The `down.sql` drops the column and the check, and forgets the consent of every order that is not a de-registration (a Neuzulassung's is incomplete without its power of attorney, and left in place it would make reapplying refuse the row); a de-registration's AGB version and time stay.
